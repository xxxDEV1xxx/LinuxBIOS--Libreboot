MAKE SURE to back up the original firmware image first:

flashprog -p internal -r factory.rom



1. Install the tools to external storage and symlink them
bash
mkdir -p /data/lib-ext/usr/bin
cp -v $L/src/coreboot/default/util/nvramtool/nvramtool $L/elf/coreboot/default/cbfstool $L/elf/coreboot/default/ifdtool /data/lib-ext/usr/bin/
for t in nvramtool cbfstool ifdtool; do ln -sfn /data/lib-ext/usr/bin/$t /usr/bin/$t; done
which nvramtool cbfstool ifdtool

After this, use cbfstool and ifdtool directly. $CBFSTOOL and $IFDTOOL also still work.

2. Hyper-Threading off (on the 2560p only)

Copy /data/lib-ext/usr/bin/nvramtool to the 2560p, then run:

bash
sudo ./nvramtool -w hyper_threading=Disable && sudo ./nvramtool -r hyper_threading

It takes effect on the next boot.

3. Add the BIOS-region write lock to the lbmk config

Insertion point: end of the file, directly after its last line.

bash
C=$L/config/module/coreboot/hp2560p_8mb/config/libgfxinit_corebootfb
cp -v $C $C.orig
[ -n "$(tail -c1 $C)" ] && echo >> $C
echo 'CONFIG_BOOTMEDIA_SMM_BWP=y' >> $C
tail -3 $C

Rebuild (this compiles edk2, GRUB and SeaBIOS, so it takes a while):

bash
cd $L && ./mk -b coreboot hp2560p_8mb 2>&1 | tail -40
find $L -newer $C.orig -name '*.rom' 2>/dev/null

The rebuilt ROM won’t contain the ME, GbE or EC blobs, so it needs the ./mk inject step that produced your current ROM. If the build or inject step fails, or inject wants a network fetch, send me the error. I’ll give you cbfstool lines to transplant the new coreboot stages into work.rom instead.

. Gate, inject grub.cfg, then IFD lock (one block, stops on any failure)
bash
cd /data/sda4/libreboot-ready/bin/hp2560p_8mb && [ -s grub.cfg ] && [ "$(strings payload.elf | grep -c password_pbkdf2)" -gt 0 ] && head -3 grub.cfg | cut -c1-60 && cbfstool work.rom remove -n grub.cfg 2>/dev/null; cbfstool work.rom add -f grub.cfg -n grub.cfg -t raw && cbfstool work.rom print | grep -n 'grub.cfg' && ifdtool -l work.rom -O final.rom && sha256sum orig.rom final.rom
If it prints nothing, a gate failed. Either grub.cfg is missing or empty, or password_pbkdf2 isn’t in the payload. Don’t flash in that case. Send me the output of ls -l grub.cfg hash.txt and wc -c grub_default.cfg.
Why the gate matters: without the password_pbkdf2 module, set superusers leaves nobody able to authenticate and the menu would be unbootable.
Expected on success: the first three lines are insmod password_pbkdf2, set superusers="root" and the hash line. Then a grub.cfg row appears in the print listing, and the two sha256 values differ.
